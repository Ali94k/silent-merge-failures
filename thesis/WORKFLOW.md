# Thesis chapter workflow (agreed 2026-07-29)

Chapters live in `thesis/` (12 chapter files + 00-spine.md + claims-ledger.md + terminology-map.md; audit records and housekeeping worklists in `thesis/audits/`).
Review runs via GitHub PRs on this repo. `gh` is installed and authenticated as Ali94k.

## Rules

- **R1 — One session = one chapter = one branch = one PR.** Branch naming `thesis/ch-NN-<slug>`. The PR touches only that chapter file (plus its own chapter-numbered figure assets, see R8).
- **R2 — Strictly sequential.** Never edit multiple chapters at once; never start another chapter until Ali explicitly requests it.
- **R3 — Shared files** (`00-spine.md`, `claims-ledger.md`, `CLAUDE.md`, repo docs) never ride in a chapter PR — separate housekeeping PR when asked.
- **R4 — Simple sentences.** Always prefer simple sentences over one big combined one; split em-dash/semicolon chains; one idea per sentence.
- **R4b — No mid-sentence insertions (ruled 2026-08-04, ch.5).** An em-dash or parenthetical aside must never interrupt a sentence's spine (subject—aside—verb). The aside becomes its own sentence; term-naming happens in its own sentence or a trailing parenthesis. Em-dashes stay legal only in display-list term glosses ("- *open coding* — proposing…"), table cells, and markers.
- **R5 — Review pushback.** Never apply review comments silently. Evaluate each against ledger, frozen evidence, and standing rules; push back in-thread with evidence when warranted; ask verification questions when ambiguous. Ali may be wrong or confuse things. Suggestion blocks apply verbatim unless factually wrong — then flag instead of applying.
- **R6 — Terminology.** "end-to-end (on real merges)", never "in vivo". "routing", not "composition", for the specialist-dispatch question. "measurement infrastructure", never "apparatus". "human annotation" + the author's "ruling", never "adjudication" in own prose. Soften deployment claims ("hard to adopt with confidence", not "blocked any principled deployment"). Committed artifact names and quoted FINDINGS terms keep original spelling, with a bridge note on first use and a row in `thesis/terminology-map.md` (amended 2026-09-09). Ruled 2026-09-02: "corroborated" / "corroboration" are banned in own prose (use "agreed with", "measured", "supporting evidence"). Ch.3 rulings (2026-07-31): "tally" → score/count; "canonical" is reserved for canonicalized forms.
- **R7 — Approved text is ruled text.** Never retro-rewritten unasked; any extension of previously approved content is explicitly flagged in the PR description.
- **R8 — Visuals.** Diagram requests come as review comments on the passage. Mermaid for flows/structure, md tables (ledger-tagged) for enumerable facts, scripted SVG (`thesis/figures/fN_M.svg` + `figures/src/fN_M.py`, reading only frozen reports data) for data charts. Figure numbers follow order of appearance. Diagrams stay number-free (any number would need a ledger tag); chart styling polish deferred to the LaTeX round.
- **R9 — Open-questions framing.** Where possible, frame literature gaps and limitations as open questions (which the RQs then answer), not as absences or deficits ("X is missing", "no study has measured X"). Hedges ("to our knowledge") still apply to the claim that a question is open. (Adopted 2026-07-30, ch.2 mini-abstract.)
- **R10 — Readability (adopted 2026-08-02, after ch.4 round 1).** (1) Gloss every project term at first use (arm, lane, gate, shape, frozen, fail-closed, …; frozen names verbatim per R6 plus a one-clause gloss). (2) One worked micro-example per mechanism the reader must otherwise simulate. (3) One component per paragraph. (4) Pin one vocabulary for recurring referents, no synonym drift (base/ours/theirs). (5) Enumerable classifications get a table before their codes are used. (6) Markers at paragraph/table ends, never mid-flow. (7) A results subsection answering a research question opens with a one-sentence, number-free answer before the derivation; tagged numbers stay in the explanation (adopted 2026-08-10, ch.6 round). (8) Parallel listings — RQ decompositions, term glosses, compared configurations, enumerated mechanisms or answers — always use display-list (bullet) structure with bold or italic run-ins, never woven prose (ruled 2026-08-07, ch.6 round 1: "Always use bullet like structure for this type of listing").
- **R11 — No money (adopted 2026-08-04, ch.5).** No dollar amounts, spend, budgets, or price envelopes anywhere in thesis prose, markers, tables, or figures. Effort is shown as machine time (wall-clock hours) and workload volume (units, passes, runs). "Cost"/"weighted cost" in the Schesch scoring sense is a metric, not money — unaffected. The repo record (runbook, FINDINGS) keeps real costs; the thesis never quotes them; appendix tables drop cost columns at build. Applies forward to ch.9's AI-use accounting.
- **R12 — First-person agency (ruled 2026-08-04, ch.5).** The author's own actions are written in first person: "I rule", "my ruling", "I ruled it row by row" — never "the author" as an actor. Applies in prose, table cells, and figure boxes. This extends first person beyond the spine's voice-in-mini-abstracts-only convention: agency statements in body prose are first-person too.
- **R13 — Calm register (adopted 2026-08-11, from the ch.6 §6.5 rewrite; reference example: ch.6 §6.5 as merged).** Prose states findings; it does not perform them. (1) A topic sentence states the claim itself, never announces that a claim is coming ("The tools' own records support the same conclusion", not "A retrospective reading sharpens the mechanism"). (2) Argument order inside a paragraph or bullet: claim, then measured evidence with its § pointer, then consequence — and the closing sentence is the consequence, never a punchline ("Neither arm met both requirements", not "Neither arm did either"). (3) No rhetorical devices: no aphorism or chiasmus ("the pattern is the lesson"), no anaphora or antithesis for effect ("There, … There, …"), no sentence fragments, no personified chapters or abstractions ("In Chapter 2 I promised", not "Chapter 2 promised"; "routing cannot improve on the backbone", not "a router has nothing to gain"). (4) No metaphor vocabulary — plain replacements per the sweep list (tally→score, arbitrage→exploit, opening→weak spot, undercut→contradicts, "did not survive"→"was not found", "respected ancestor"→"has precedent in"; the list grows as Ali flags words). (5) Every generalization carries its scope inline ("on its gate pool", "in the measured sample"). (6) Normal word order — no fronted objects ("I ruled the signal suggestive only", not "The signal I ruled…"). (7) Reserved terms stay reserved: *verdict* only for gate outcomes, *flip* only for the route-map change ("repaired environment/scoring" stays the merged ch.3/ch.5 term for the scoring fix; the flip gloss does not claim "repair"). Scope: all thesis prose; mini-abstracts and bridges keep the narrative-voice convention but obey (3)–(7). **Carve-out to (3), ruled 2026-09-07 (compliance audit):** chapters, sections, tables, and figures may be the grammatical subject of *navigational* verbs — reports, states, lists, examines, carries, gives, shows, turns to — because that is cross-reference, not personification ("Chapter 6 reports the verdicts" is compliant). The ban still applies to agentive verbs on chapters ("Chapter 2 promised") and to all abstractions and non-persons as actors ("the oracle condemned", "the project learned", "conservatism earns").
- **Light register (ruled 2026-09-02, ch.10 r11).** Chapters 10 (from r7), 11 and 12 are drafted in the direct explanatory register: short plain sentences, mechanisms spelled out, no contractions; R13's hard rules and the marker conventions still apply. Compression is the top fact-drift risk, so every compression pass gets its own fact check against the frozen record.

## Draft conventions (validated in ch.1)

- Every empirical number is a claims-ledger value tagged `[MacroName]` immediately after it, value-exact. Numbers without a ledger row → `[TODO-LEDGER: description]`, never inlined.
- External references → `[CITE: author, venue year — topic]` placeholders; never fabricated.
- Frozen-artifact terms renamed for the thesis → inline `[MAP: thesis name ← frozen name(s), where frozen]` markers, swept into `thesis/terminology-map.md` by a housekeeping PR (the map is a shared file per R3, never in a chapter PR). Entry criteria are tight: only terms that appear in frozen artifacts and were renamed or need disambiguation — not a general glossary.
- Chapter structure: header line (`Budget · Status · Narrative`, with an optional serves/RQ segment where useful — merged chapters carry no standalone RQ segment), Zeller-style mini-abstract blockquote, numbered sections, Bridge blockquote, Figures list, Claims-used list reconciled to the tags actually in prose.
- Before every push: verify all tags exist in the ledger, values match, and the Claims-used list equals the prose tag set.
- Pre-push protocol (from ch.5 on): multi-agent fresh-reader diagnosis (examiner/student/editor personas) plus a fact-drift verification pass against the frozen record BEFORE the first push, not after review. Readability rewrites get the same fact-drift check every time.

## Review-round mechanics

1. Ali reviews on github.com / mobile: inline comment = directive, suggestion block = authoritative edit, Approve / Request changes = status.
2. Ali says "review submitted" in chat → Claude ingests via `gh` (reviews + inline comments + conversation comments).
3. Apply per R5, verify tags, commit with itemized message, push, reply in each thread quoting the change + commit SHA.
4. Merging is Ali's action. After merge: sync main, delete the branch.
5. **External reviewer (comment-only, agreed 2026-08-03):** invited as a collaborator (the GitHub role is write, checked 2026-09-14 in end-game step 4, so the comment-only role holds by agreement, not by permission); reviews MERGED chapter PRs directly (Files changed stays commentable post-merge; approve/request-changes are not used by them, by agreement — comment reviews only). The reviewer must press Submit review — another account's pending review is invisible to the API. Ingest the same way as Ali's rounds; R5 pushback applies to their comments too; fixes go through the chapter's next revision PR; Claude replies are 🤖-prefixed (the reviewer's identity is their own — no prefix on their side).

## Adopted process conventions (assessment, 2026-07-29)

1. **🤖 prefix** on every Claude-written PR reply/comment — `gh` posts as Ali94k, so the prefix distinguishes voices in the record (matters for Ch. 9). A separate machine account is the cleaner alternative if ever wanted.
2. **Pending-review check**: before replying in threads, Claude checks for an open pending review (it blocks same-account inline replies → fall back to a Conversation-tab comment; pending comments are readable via the API when needed).
3. **Rendered-visual feedback comes via chat** (screenshot + instruction) or as comments on the Mermaid source lines — PR diffs show diagram source, not the rendering. No extra tooling.
