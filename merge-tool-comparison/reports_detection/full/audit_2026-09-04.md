# Audit — `reports_detection/full/hit_adjudications.md`

Audited 2026-09-04. Target: the FINAL §4.6 Stage-C hit-adjudication record (76 lines, commit `86d8a6c`).
Method: 8 evidence dimensions swept in parallel, HIGH/BLOCKER findings adversarially re-derived, then
every load-bearing claim re-verified by hand against `raw_results.json`, `summary.txt`, `scenarios.csv`,
`adjudication_ui.html`, the frozen detector source, and the two post-fix runs.

## Verdict

The arithmetic is clean. The **rulings are not**. Two of the eleven CAUSAL rows do not survive
inspection of the merged source, and the sentence that insulates the positives from the two known
detector defects is false — falsified by the project's own post-fix runs 13 days after this file was
marked FINAL. Three further rows quote site counts that do not match the merged file.

Headline effect: **11 CAUSAL of 164 (6.7% [3.8, 11.6]) → 9 CAUSAL of 164 (5.5% [2.9, 10.1])**, and
"100% flag precision on the positives" → 9/11 = 82%.

---

## BLOCKERS — a cited ruling or number is wrong

### B1. `tcurdt_jdeb` is not CAUSAL; it is the `(`-defect

The file says: *"the single bare use of `compression` at L95 is the only occurrence in merged (no
surviving declaration), `options` is the live declaration at L87 → stale reference = compile error."*

Merged source:

```
L87:  BigInteger buildData(..., TarOptions options) throws ... {
L95:      options.compression().toCompressedOutputStream(new FileOutputStream(output))
```

`compression` at L95 is a **method invoked on the live `TarOptions options` parameter**. It needs no
in-file declaration. Nothing is stale, nothing fails to compile. The flag fires only because
`_scan_stale_var_refs` lacks the `(`-exclusion — the exact defect the file attributes to the controls
alone. `dev_eq` is `True` for this file, and the flagged line is byte-identical in `theirs`, so
criterion (ii) ("in the merged file but in neither parent") also fails.

This is the one row the draft explicitly marked **verify**; the verification confirmed a false site.

*Confirmed by the runs:* both `postfix/` and `postfix2/` drop tcurdt — `via detector FLAG: 10`.
`CLAUDE.md` already records it as "retired as defect-dependent". The FINAL file was never amended.

**Fix:** relabel DETECTOR-FP.

### B2. `atam4j` — L27 is the declaration; the file compiles

The file says: *"4 stale callers of the old name (merged L27/46/51/59) = compile error."*

Merged source:

```
L27:  public Response getTestRunResultFromServer(String testsURI) {     <- the DECLARATION
L34:  public Response getCriticalTestRunResultFromServer() {
L46:      return getTestRunResultFromServer(getTestsURI() + "/" + category);
L51:      return getTestRunResultFromServer(getTestsURI());
L59:      () ->  getTestRunResultFromServer(getTestsURI()));
```

Both names are declared. The three calls pass a `String` and bind to L27. There are three callers, not
four, and none is stale — no compile error exists. The call lane (`_scan_stale_callers`) has no
declaration guard at all, so it counts the surviving declaration as a "stale caller".

The rename itself is a detector artifact: `theirs` **keeps** the old method and **adds** the new one.

Worse for criterion (iii): the real merge-induced breakage is in the merge's **other, unflagged** file.
Merged `PassingTestAcceptanceTest.java` L38 uses `PassingTest.class` while its import block (taken from
`ours`) imports only `PassingTestWithNoCategory`. That file was scored CLEAN by all five detectors. The
flag does not explain the test failure; the detectors missed the thing that did.

**Fix:** relabel DETECTOR-FP, and record the sibling-file miss — it is a real, citable false negative.

### B3. "No positive (CAUSAL) hit depends on either defect — confirmed during adjudication" is false

Stated as an adjudication-verified fact. It is not:

- tcurdt depends entirely on defect (a) — see B1. Post-fix: 11 → 10 flagged positives.
- `softinstigate_restheart` loses 2 of its 5 RM2 sites to the same fix (L255 `request()`, L260
  `response()` are method declarations).

The accompanying prediction ("the post-fix run is expected to leave R2 unchanged while driving R1
toward 0") was falsified on the R2 half. STATUS.md:189 and ISSUES.md:698 repeat the refuted sentence
beside the correction, so each contradicts itself.

### B4. The control root-cause decomposition is wrong

The file attributes the four control FPs to defect (a) "(3 merges)" and defect (b) "(1 merge)".
After **both** stated one-line fixes shipped, `postfix/summary.txt` still reports **3/193 blocked** —
cloudfoundry ×2 and podam were still flagged. Only aerospike was cleared by the two fixes. The rest
needed a third, unlisted defect class (declaration guard blind to generics wildcards and to lambda
parameters), which is what `postfix2` fixed to reach 0/193.

The podam row's specific mechanism claim is also wrong: the declaration line survives the corrupted
stripping (it *is* the first reported line), so the newline bug shifted coordinates but did not blind
the guard — the wildcard `?` in `Class<? extends Map<?, ?>> mapType =` did.

## HIGH — claims unsupported or materially misleading

### H1. Site counts that do not match the merged file

| row | file says | actual |
|---|---|---|
| softinstigate_restheart | "7 stale sites" | 7 flag *records* across 2 lanes = 5 distinct lines; L255/L260 are method declarations → **3 genuine stale sites** (L138/141/143) |
| jcabi RtHooksITCase | "4 stale callers (L60/99/122/154)" | L154 is the declaration `private static Repo repo(final Repos repos)`; L99/L122 pass a `Repos` and resolve to it → **1 genuine stale caller** (L60, zero-arg `repo()`) |
| comatoes | "RM2 ×2" implied by lanes=both | L105 is a qualified call `shipState.setReservePowerCapacity(...)`, L468 is the declaration → **0 genuine RM2 sites** (the row already disclaims this lane) |

Both merge-level rulings still stand — softinstigate on the Joern lane, RtHooks on L60 — but an examiner
who opens L154 or L255 sees the record citing a declaration as evidence of a stale call.

### H2. "resolvable in neither parent" is inverted

Quoted verbatim for `datastax_java-driver` and `jdupl_lancoder`. The detector's own comment
(`unresolved_reference.py:30`) states the real semantics: it fires on names unresolved in merged but
**not in either parent's unresolved set** — i.e. names that *did* resolve in the parents. The emitted
message text says the opposite, and the record copies it.

For datastax: `AtomicBoolean isShutdown` is declared at L53 in **base and theirs** (absent in ours).
So it resolved in two parents. The ruling is right (merged L134 `isShutdown.get()` has no field to bind
to — only the method `isShutdown()` at L372); the stated reason is backwards.

### H3. "Detector-flag precision on positives: 11/11 = 100%" is a conditional quantity

Conditioning on `Tests_failed` and calling the result "precision" invites the reading that the detector
is right ~100% of the time. Overall flag precision across all 15 ruled flags is **11/15 = 73%
[48.0, 89.1]** before the corrections above, **9/15 = 60% [35.7, 80.2]** after. The claim also carries
no interval, unlike every other proportion in the file.

Unit conflation compounds it: "15 flags" are flagged *files* (which happen to be 15 distinct merges);
the underlying detector flag records number 54.

### H4. The adjudication was not blind, and "zero overrides" is sold as corroboration

`make_adjudication_ui.py` hard-codes a `DRAFTS` dict giving each of the 15 flags a pre-filled label
**and a full argued rationale**, rendered above the evidence in a `draftBox` with a
`<button onclick="accept()">✓ Accept draft</button>` and a single-key `a` shortcut that accepts and
auto-advances. Every draft label was CAUSAL or DETECTOR-FP; the middle label REAL-BUT-INCIDENTAL was
never proposed for any item, and the tally records 0 uses of it.

The Protocol paragraph enumerates the evidence shown and conspicuously omits the draft label from that
list. "Every draft label was accepted, zero overrides" is presented as a strength; under a one-key
accept flow it is equally consistent with assent. One rater, no second rater, no inter-rater agreement,
and the arm chip (POSITIVE/CONTROL) plus the ground-truth test outcome were displayed on every item —
none of which the file discloses.

The comatoes row ending "mostly agrees with the draft" is a partial disagreement inside a record whose
header asserts zero overrides.

### H5. CAUSAL is inferred, never observed

Criterion (iii) is answered by reading merged source. No build log, compiler invocation, or failing-test
output was consulted or rendered. "Plausibly explains" is reported as "CAUSAL" and cited downstream as
"real silent failures caught". atam4j (B2) is exactly the failure mode this invites. The pre-registered
flaky/environmental-failure spot-check is not reported as performed.

### H6. Thesis prose welds two different detector configurations

`thesis/01-introduction.md:58` and `00-spine.md` pair the frozen run's catch (11/164, suite `843e5f5`)
with the post-fix control record (0/193, suite `f964354`). No single configuration produced both: the
suite measuring 0/193 no longer claims tcurdt. The record states both halves side by side without
flagging that they are different instruments.

## MEDIUM — disclosure gaps

- **No committed ruling artifact.** The UI persisted rulings to browser `localStorage`; its CSV export
  was never committed. The audit trail for "15/15 ruled, zero overrides" is this document's own
  assertion. Later rounds in this project *did* commit theirs (`sd6_rulings.csv`,
  `phase3_reliability_rulings.csv`, `category_mapping_adjudicated.csv`) — Stage C is the outlier.
- **Freeze caveat dropped.** `summary.txt` line 1 warns "an uncommitted working tree still reports the
  last commit". The freeze is the central defence against the G2 overfitting threat, and two defects
  were found mid-run, so the caveat matters here more than anywhere. It is absent from this file.
- **`merged == dev` for 4 of 11 positives** (ahome-it, datastax, jcabi RtGist, tcurdt) — the UI computed
  `dev_eq` and displayed it; the record never mentions it. *This is not an argument against the rulings*
  — these are merges whose developer resolution failed its own tests, so reproducing it is expected and
  arguably strengthens causality. But it is a fact a reader will want, and it is the frame in which the
  atam4j miss becomes visible.
- **8 of 164 positive merges and 1 of 193 controls were scored on a partial file set** (some files
  dropped at file-level divergence, others kept). Only the all-files-diverged case is disclosed.
- **Wilson intervals assume independent trials.** The 164 positives come from 113 repositories (jcabi
  contributes 2 of the 11 catches; cloudfoundry 2 of the 4 false blocks). Clustering is not disclosed.
- **§4.7 miss list never delivered.** The file defers the complement of its headline to it;
  `misses_to_classify.csv` sits beside it with 152 rows and **0** judgements filled.
- **Two of the eleven positives are the pilot's own hits** (erudika, jacquesberger). v2 was
  pilot-informed and the pilot merges are a subset of this population, so "pilot hit reconfirmed" is
  in-sample. FINDINGS.md discloses this; this file does not.
- **No per-lane decomposition** of either rate, though the whole controls discussion is about one lane.
- **`FINDINGS.md` says "5 are dual-lane corroborated"; the correct count is 4** (ahome-it, comatoes,
  erudika, softinstigate). This file's lanes column is right — FINDINGS.md is wrong, and the error has
  propagated onward.
